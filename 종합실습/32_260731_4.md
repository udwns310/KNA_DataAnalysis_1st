지금까지 배운 거 다 끌어모아서 푸는 실습 3개.

대부분은 몰라서 못 푸는 게 아니라 안 떠올라서 못 푸는 거임.
막히면 힌트부터 보지 말고, 요구사항 1번부터 한 줄씩 코드로 옮기기.
전부 배운 범위 안에서만 풀림 (`def`, 딕셔너리 안 씀 > 아직 안 배웠으니 안 써도 됨)

### 시작하기 전에

- 실습마다 새 `.py` 파일 하나씩 만들어서, 문제에 주어진 데이터를 그대로 복붙하고 시작하기

  > 구분선은 `print("=" * 40)` 처럼 문자열 곱하기로 만들면 편함

## 실습 1. 설비 종합 모니터링 리포트

### 상황

공장 설비들의 `(설비명, 온도, 진동)` 데이터가 튜플 리스트로 주어짐.
이걸 분석해서 한눈에 보기 좋은 "모니터링 리포트"를 출력하는 게 목표.

```python
sensors = [
    ("컨베이어_01", 78, 2.1),
    ("용접기_02", 92, 5.4),
    ("절단기_03", 85, 3.2),
    ("건조로_04", 101, 6.8),
    ("냉각탑_05", 67, 1.5),
    ("도장부스_06", 88, 4.1),
    ("성형기_07", 90, 2.9),
]
# (설비명, 온도, 진동)
```

### 요구사항

1. 각 설비 상태를 아래 기준으로 판정해서 번호 붙여 한 줄씩 출력
   - 온도 > 90 또는 진동 > 5.0 > "위험"
   - 온도 >= 80 또는 진동 >= 3.0 > "주의"
   - 그 외 > "정상"
2. 정상 / 주의 / 위험 각각 몇 대인지 세서 출력
3. 전체 중 이상 설비(주의 + 위험) 비율을 % 로 출력 (소수 첫째 자리 반올림)
4. 전체 평균 온도 출력 (소수 첫째 자리 반올림)
5. 온도가 가장 높은 설비 이름 + 온도 출력 (반복문으로 직접 찾기)
6. "위험" 설비 이름만 모아서 정렬해 리스트로 출력

### 써야 하는 개념

튜플 리스트 / 언패킹 / `for` / `enumerate` / `if-elif-else` / `or` / 비교연산자
복합연산자(`+=`) / `round` / `len` / `.append()` / `.sort()` / f-string / 누적변수

### 예상 출력

```
========================================
        설비 종합 모니터링 리포트
========================================
1. 컨베이어_01 | 온도 78℃ | 진동 2.1mm/s | 정상 ✅
2. 용접기_02 | 온도 92℃ | 진동 5.4mm/s | 위험 🚨
...
----------------------------------------
총 설비: 7대
정상: 2 / 주의: 3 / 위험: 2
이상 설비 비율: 71.4%
평균 온도: 85.9℃
최고 온도 설비: 건조로_04 (101℃)
위험 설비 목록: ['건조로_04', '용접기_02']
========================================
```

### 유의할 점

- `성형기_07`은 온도가 **90** > 이건 `> 90` 이 아니라 `>= 80` 에 걸림 > "주의"
  경계값 헷갈리기 쉬우니 부등호 방향 유의
- 판정 순서 중요 > 위험을 먼저 걸러야 함 (`elif` 순서 잘못 짜면 다 주의로 빠짐)

### 도전 과제

위험 설비가 1대라도 있으면 맨 마지막에 `⚠ 즉시 점검 요망`,
한 대도 없으면 `✅ 전 설비 안정` 출력해보기.

## 실습 2. 실시간 측정값 입력 시스템

### 상황

작업자가 측정값을 계속 입력함. 근데 몇 번 입력할지는 정해져있지 않음.
그래서 `while` 로 계속 받다가 `q` 입력하면 종료하고,
그동안 모인 값들 통계를 뽑는 게 목표.

> 횟수가 정해진 반복은 `for`, 언제 끝날지 모르는 반복은 `while`

### 요구사항

1. `측정값: ` 을 계속 입력받다가 `q` 입력하면 반복 종료 (`break`)
   - 입력값은 무조건 숫자 아니면 `q` 라고 가정
2. 입력값이 100(임계값) 초과하면 그 즉시 경고 + 지금까지 초과 횟수 출력
   (경고만 하고 반복은 계속됨)
3. `q` 로 끝난 뒤:
   - 입력값이 하나도 없으면 `입력된 측정값이 없습니다.` 출력하고 끝
   - 값이 있으면 아래 출력
     - 총 입력 개수
     - 최댓값 / 최솟값 (반복문으로 직접 찾기)
     - 평균값 (소수 둘째 자리 반올림)
     - 임계값 초과 개수
     - 평균보다 큰 값의 개수 > 평균을 먼저 구한 뒤 다시 세야 함
     - 상위 3개 값 (내림차순 정렬 후 슬라이싱)

### 써야 하는 개념

`while True` / `break` / `input` / `float()` 형변환 / 문자열 비교 / `.append()`
`len` / 누적변수 / `for` / 비교연산자 / `if-else` / `round` / `.sort()` / 슬라이싱

### 예상 출력

```
=== 실시간 측정값 입력 시스템 ===
측정값을 입력하세요. 종료하려면 q 입력.
측정값: 85
측정값: 120
  🚨 임계값(100) 초과! 현재까지 초과 1회
측정값: 60
측정값: q
----------------------------------------
총 입력 개수: 3개
최댓값: 120.0 / 최솟값: 60.0
평균값: 88.33
임계값 초과 개수: 1개
평균 초과 개수: 1개
상위 3개 값: [120.0, 85.0, 60.0]
```

### 유의할 점

- `input` 으로 받은 값은 무조건 str > 숫자로 쓰려면 `float()` 로 변환
- `q` 인지 아닌지는 **변환하기 전에** 문자열 상태로 먼저 비교하기
  (`q` 를 `float()` 하면 에러남)
- "평균보다 큰 값 개수"가 이 문제의 핵심 > 평균을 다 구하기 전에는 셀 수 없음
  > 리스트를 두 번 도는 게 맞음 (한 번은 합계용, 한 번은 개수 세기용)
- 값이 3개 미만이어도 "상위 3개"는 슬라이싱이라 알아서 있는 만큼만 나옴 (에러 안 남)

### 도전 과제

`q` 대신 그냥 Enter(빈 입력) 치면 `""` 가 들어옴.
빈 입력은 무시하고 다시 받도록 `if` 로 처리해보기.

## 실습 3. 교대조 센서 경고 로그 분석

### 상황

오전조 / 오후조가 각각 "경고 뜬 센서 번호"를 순서대로 기록함.
같은 센서가 여러 번 경고 울리면 그만큼 여러 번 적힘.
두 로그를 비교/분석하는 게 목표.

```python
morning   = ["TZ_11", "TZ_13", "TZ_11", "TZ_15", "TZ_13", "TZ_11", "TZ_11", "TZ_17"]
afternoon = ["TZ_13", "TZ_15", "TZ_13", "TZ_19", "TZ_15", "TZ_21", "TZ_13", "TZ_15"]
```

### 요구사항

1. 오전조 / 오후조 각각 "고유 센서 종류 수" + 정렬된 목록 출력
   (`set` 으로 중복 제거 > `sorted` 로 정렬)
2. 두 조 모두에서 경고 난 센서(교집합) 정렬해서 출력
3. 오전조에만 있는 센서 / 오후조에만 있는 센서(차집합) 각각 정렬해서 출력
   > 차집합은 방향에 따라 결과가 다름 (오전-오후 랑 오후-오전 은 다른 거)
4. 전체 경고 센서(합집합) 종류 수 + 정렬된 목록 출력
5. 전체 센서마다 `오전 횟수 + 오후 횟수 = 총 경고 횟수` 구해서
   `(횟수, 센서명)` 튜플 리스트 만들고, 횟수 많은 순으로 정렬해서
   `N위: 센서명 - X회` 형태로 출력
6. 가장 경고 많았던 센서 콕 집어서 "우선 점검 필요" 출력

### 써야 하는 개념

`set` / `set()` 중복 제거 / 집합연산(`&` `-` `|`) / `sorted()` / `.count()`
튜플 만들기 / 튜플 리스트 정렬(`sorted`, `reverse`) / `for` / `enumerate` / 언패킹

### 예상 출력

```
=== 교대조 센서 경고 로그 분석 ===
오전조 고유 센서 4종: ['TZ_11', 'TZ_13', 'TZ_15', 'TZ_17']
오후조 고유 센서 4종: ['TZ_13', 'TZ_15', 'TZ_19', 'TZ_21']
----------------------------------------
양 교대조 공통 경고 센서: ['TZ_13', 'TZ_15']
오전조 전용: ['TZ_11', 'TZ_17']
오후조 전용: ['TZ_19', 'TZ_21']
전체 경고 센서 6종: ['TZ_11', 'TZ_13', 'TZ_15', 'TZ_17', 'TZ_19', 'TZ_21']
----------------------------------------
경고 발생 횟수 순위:
  1위: TZ_13 - 5회
  2위: TZ_15 - 4회
  3위: TZ_11 - 4회
  ...
----------------------------------------
최다 경고 센서: TZ_13 (5회) → 우선 점검 필요
```

### 힌트

- 어떤 센서가 오전 로그에 몇 번 나왔는지 > `morning.count("TZ_13")`
- 집합연산 결과(`set`)는 순서가 없음 > 출력 전에 `sorted()` 하면 깔끔하게 나옴
- `(횟수, 센서명)` 순서로 튜플을 담으면 > `sorted(..., reverse=True)` 했을 때
  자동으로 횟수 기준 내림차순 정렬됨 (앞에 있는 값 기준으로 정렬되니까)

### 도전 과제

총 경고 3회 이상인 센서만 골라서 "집중 관리 대상" 리스트 따로 만들어 정렬해서 출력.
(5번에서 만든 튜플 리스트 재활용 + `if` 로 걸러내기)

3. 그래도 안 되면 그때 힌트 보기

다 풀면 왜 이렇게 짰는지 옆 사람한테 설명해보기 > 설명되면 진짜 아는 거임.
